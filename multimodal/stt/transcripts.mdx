title: "/transcripts endpoint"
description: "REST · async batch transcription with the same BH calibration as the live endpoints."
--- `/api/transcripts` is the **REST batch transcription** surface — upload a recorded encounter, get a structured transcript + instrument scores back. Same engine, same DSM-5-TR vocabulary bias, same C-SSRS safety check as `/sessions` and `/transcribe`. ## Upload ```http
POST /api/sessions/{id}/recordings
Content-Type: multipart/form-data
``` Limits: 60 minutes audio, 150 MB file. See [Audio Configuration](/multimodal/stt/audio). ## Trigger transcript ```http
POST /api/sessions/{id}/transcripts
Content-Type: application/json { "language": "en-US", "diarization": true, "speakers": 2, "instruments": ["phq-9", "gad-7", "c-ssrs"], "vocabulary": { "formulary": [...], "programs": [...] }
}
``` ## Poll status ```http
GET /api/sessions/{id}/transcripts/{transcript_id}/status
``` Status: `processing` → `completed` | `failed`. ## Retrieve ```http
GET /api/sessions/{id}/transcripts/{transcript_id}
``` Returns the same structured shape `/sessions` returns at finalize — transcript, diarization, instrument scores, codes, SOAP draft. <Note> Async batch accuracy may be slightly lower than the real-time endpoints because batch loses interactive context (no in-the-moment vocabulary biasing). Pass the practice vocabulary on every request for parity.
