The Agentic Framework is built around two pillars: the **canvas workflow engine** (backend) and the **care orchestrator** (AI services). Both share the event bus and the tenant audit trail.

```mermaid

  C[Canvas frontend<br/>AgentBuilderContext · AgentCanvas]
  C -->|REST + Socket.IO| BE[Backend<br/>/api/agent-workflows<br/>/api/deployments<br/>/api/care-orchestrator proxy]
  BE -->|Auth · TenantContext · PHI Audit · Subscription| ENG[workflow-engine]
  ENG --> WE[WorkflowExecutor 471L]
  ENG --> EC[ExecutionContext 354L]
  ENG --> WQ[WorkflowQueue 285L<br/>Bull · Redis DB 2 · 5 workers]
  BE -.->|Service Key| AI[AI Services]
  AI --> CO[Care Orchestrator]
  CO --> AGT[AgentType enum]
  CO --> SM[Workflow State Machine 30+ states]
  CO --> EB[Event Bus]
```

## Workflow execution

```mermaid
sequenceDiagram
  participant Client
  participant Backend
  participant DB
  participant Queue as WorkflowQueue
  participant Worker
  participant Executor as WorkflowExecutor
  participant Socket as Socket.IO

  Client->>Backend: POST /api/agent-workflows/:id/execute
  Backend->>DB: INSERT agent_workflow_executions (status=pending)
  Backend->>Queue: queueWorkflowExecution(executionId, ...)
  Note over Backend,Queue: Falls back to sync if Redis unavailable
  Backend-->>Client: { executionId }
  Queue->>Worker: dispatch job
  Worker->>DB: load execution + version snapshot
  Worker->>Executor: execute(executionId, organizationId)
  Executor->>DB: SET LOCAL app.current_organization_id
  Executor->>Executor: traverse graph<br/>_executeNode → NodeRunner.execute()
  Executor->>Socket: workflow:node:executing
  Executor->>Socket: workflow:node:completed
  Executor->>DB: UPDATE agent_workflow_executions (status=completed)
  Executor->>Socket: workflow:execution:completed
```

## Tenant isolation

Background workers obtain a Postgres connection and immediately run `SET LOCAL app.current_organization_id = '<org_id>'` inside a transaction. RLS policies enforce that every read and write is filtered by `organization_id`.

## Versioned execution

For published executions, the executor loads the immutable snapshot from `agent_workflow_versions`. Draft edits made to the same workflow after the publish do **not** affect running executions.

## Queue + retry

```
WorkflowQueue (Bull)
  ├─ Redis DB 2 (separate from sessions)
  ├─ retry: 3 attempts with 5 s exponential backoff
  ├─ job staleness: 60 s interval, 2 stalled threshold
  ├─ TTL: 100 completed jobs, 50 failed jobs kept
  ├─ concurrency: 5 workers
  └─ graceful sync fallback if Redis is unavailable
```
