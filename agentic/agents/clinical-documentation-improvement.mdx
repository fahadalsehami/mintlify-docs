<Info>
  **Category:** Documentation & Coding &nbsp;·&nbsp; **Signals:** Clinical note · Specialty rule-set · Severity qualifiers · Audit trail
</Info>

Concurrent CDI on every note — surface specificity, severity, and completeness gaps as clinical queries, log every accept/reject.

## Configuration

| Field | Description |
| :--- | :--- |
| `specialty_ruleset` | Specialty CDI rule-set (BH, primary care, …) |
| `thresholds` | Practice documentation thresholds |
| `audit_retention` | Audit retention + rationale requirements |
| `enforcement` | Sign-off enforcement (advisory vs. blocking) |

## Execution

1. Reads the note against the CDI rule-set for the specialty
2. Surfaces missing specificity (e.g. uncomplicated → with severity)
3. Suggests language clinicians can paste into the note
4. Logs the rationale for every suggestion
5. Records the clinician's accept/reject decision

## Composable experts

| Expert | Role |
| :--- | :--- |
| **CDI Rule Expert** | Specialty rule-set adherence |
| **Specificity Expert** | Highest defensible diagnosis specificity |
| **Severity & Acuity Expert** | Capture of clinically relevant qualifiers |
| **Audit Trail Expert** | Every suggestion logged with rationale |

## Compliance guarantees

<Warning>
- CDI suggestions are surfaced as clinical queries, never code changes
- Every suggestion logs the rationale and the rule it tested
- Audit retention follows the practice policy by default
</Warning>

## Endpoints

REST: `POST /api/therapy/validate-note` · `POST /api/therapy/suggest-codes` (with `mode: 'cdi_review'`).
